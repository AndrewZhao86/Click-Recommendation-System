# Phase 8 — Verification Artefacts

Generated by the Phase 8c load-test sweep (`make loadtest`,
`make loadtest-llm`, `make loadtest-sweep`). Drop the four screenshots
described below into `docs/img/` after each run; the README links to
this page.

## How to regenerate every artefact

```bash
cp .env.example .env
echo "GOOGLE_API_KEY=$YOUR_KEY" >> .env
echo "OTEL_EXPORTER=jaeger" >> .env

make install
make up-obs                   # Kafka + Redis + Postgres + Kafka UI + Jaeger
make migrate
make seed                     # writes artifacts/seeded_users.txt
make api &
make consumer N=3 &
make replay EVENTS=20000      # warm caches + populate items:top:_global

make loadtest                 # → artifacts/locust_report.html
make loadtest-sweep           # → artifacts/throughput_vs_consumers.csv
make loadtest-llm             # → artifacts/locust_llm_report.html
```

## Scalability proof — throughput vs consumer count

Source: [`artifacts/throughput_vs_consumers.csv`](../artifacts/throughput_vs_consumers.csv).
Expected shape: max RPS rises near-linearly N=1 → N=3 → N=6 (the 6
partitions on `user.clicks` cap parallelism at 6, so further N gives
diminishing returns by design).

Quick plot:

```python
import csv, matplotlib.pyplot as plt
rows = list(csv.DictReader(open("artifacts/throughput_vs_consumers.csv")))
plt.plot([int(r["consumers"]) for r in rows], [float(r["max_rps"]) for r in rows], "o-")
plt.xlabel("consumers"); plt.ylabel("max RPS"); plt.savefig("docs/img/throughput_vs_consumers.png")
```

## Trace correlation — one `event_id` across API + consumer


## Failure modes covered

- Redis down → `redis-cli SHUTDOWN NOSAVE`; `/search` keeps returning
  200 with hybrid scores (Postgres-only fallback).
- LLM down → `unset GOOGLE_API_KEY`; `/search?use_llm=true` returns the
  hybrid order with `llm_rationale=null`.
- Consumer killed mid-load → rebalance completes < 30 s; no message
  loss visible in Kafka UI.
